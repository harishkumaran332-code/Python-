Rumors have a frequency

FSRU is a rumor detector that reads a post’s text and image together, then makes its decision in the frequency spectrum instead of the raw features.

The problem

Social media posts rarely carry one kind of evidence. A rumor might pair a dramatic caption with a recycled photo. Detectors that look at text alone, or image alone, miss mismatches between the two, so modern ones combine both.

The hard part is how to combine them. Text and image features live in very different spaces, and simply concatenating them lets noise from one side leak into the other.

The idea

Any feature vector can be written as a sum of waves, from slow and broad to fast and fine. A Fourier transform makes that view explicit. In the paper (Lao et al., AAAI 2024), text and image features are moved into this spectrum, where a learnable filter decides which frequencies carry useful signal and which are noise, and the two modalities are fused there.

The demo above is the intuition: a fixed cutoff is a blunt tool. FSRU learns its filters from data instead.

How the pipeline runs

1. Encode the text

Words become 32-dimensional embeddings, padded or cut to 50 tokens.

2. Encode the image

The 224 × 224 image is split into 16 × 16 patches, like a Vision Transformer.

3. Move to the spectrum

Both feature sets go through a Fourier transform.

4. Filter and fuse

A learnable filter bank keeps the useful frequencies, and the two spectra are combined.

5. Classify

The fused features give a label: rumor or non-rumor. Extra loss terms, weighted by alpha and beta, help align the two modalities.

My run

I ran the code in Google Colab on a T4 GPU with the Weibo dataset, which pairs Chinese tweets with images and labels each one as rumor or non-rumor.

Three things needed fixing along the way:

Memory. The loader holds every image in RAM, so I limited it to the first 1,500 images from each folder, 3,000 in total.

Data format. The download contained raw tweet text files, not the CSV files the code reads. I wrote a short conversion step that tokenizes the Chinese text with jieba and builds the train and test CSVs.

Embeddings. There was no pretrained word2vec file, so the text embeddings start from random vectors, which the code supports.

Results (accuracy and F1 from the k-fold run) will be added here once the training finishes.
